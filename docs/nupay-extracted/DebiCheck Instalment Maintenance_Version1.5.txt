   1. Disclaimer
The DebiCheck payment stream is still under development, thus this document is subject to
change and it is not the final draft.

   2. Introduction
This document describes the DebiCheck full function webservices for instalment
maintenance:

   •   Add an instalment
   •   Maintain an instalment
   •   Reschedule an instalment
   •   Cancel an instalment
   •   Re-activate an instalment
   •   Recall an instalment

   2.1.    System Overview
The merchant will be sending a request type to NuPay via webservices. NuPay needs to
accept the request and authenticate the merchant using the authentication string. Once
authentication has taken place the data sent through will be processed. All requests are
handled by the below mentioned methods of the webservice.

   2.2.    Security
Security measures include the use of Secure Sockets Layer (SSL) for the connection. It is
required to use https instead of the normal http when connecting to the server.

   2.3.    Best Practice for Webservice Consumption
The webservices adhere to the Restful standard, which dictates that the input and output is
Json data. RESTful web services are built to work best on the web.
Representational State Transfer (REST) is an architectural style that specifies constraints,
such as the uniform interface, that if applied to a web service induce desirable properties,
such as performance, scalability, and modifiability, that enable services to work best on the
web.
The suggested method of using this web service is to supply a JSON call with all the input
parameters.

    1. System Inputs
    1.1.     Add Instalment
This method adds a new instalment to the existing mandate. All the inputs below are
required. The submit date must be in line with the original mandate. The mandate must be
active.
The following inputs apply in JSon format:
{
            "auth":"",
            "mandateID":"",
            "cardAcceptor":"",
            "instalment":"",
            "amount":"",
            "trackingIndicator":"",
            "submitDate":""
}

    1.2.     Instalment Maintenance
This method allows maintenance to be done on an instalment. Only the amount, tracking
indicator and submit date can be maintained on an instalment. Only active future instalments
can be maintained. The following inputs apply in JSon format:
{
            "auth":"",
            "mandateID":"",
            "cardAcceptor":"",
            "instalment":"",
            "amount":"",
            "trackingIndicator":"",
            "submitDate":"",
           "applyToAll":
}

    1.3.    Instalment Reschedule
This method allows an instalment to be rescheduled. Only a failed instalment can be
rescheduled. All inputs are required. The date and the tracking of the failed instalment can
also be updated.
The following inputs apply in JSon format:
{
           "auth":"",
           "mandateID":"",
           "cardAcceptor":"",
           "instalment":"",
           "amount":"",
           "trackingIndicator":"",
           "submitDate":""
}

    1.4.    Instalment Cancellation
This method allows an instalment to be cancelled. Only active future instalments can be
cancelled.
The following inputs apply in JSon format:
{
           "auth":"",
           "mandateID":"",
           "cardAcceptor":"",
           "instalment":"",
           "amount":"",
           "trackingIndicator":"",
           "submitDate":""
}

    1.5.    Instalment Re-activate
This method allows a cancelled instalment to be re-activated. Only future instalments can be
reactivated for their original submit date.
The following inputs apply in JSon format:


{
           "auth":"",
           "mandateID":"",
           "accessID":"",
           "instalment":"",
           "startDate":""
}



    1.6.    Instalment Recall
This method allows an instalment to be recalled. Only instalments that are in an ‘In Tracking’
state can be recalled.
The following inputs apply in JSon format:


{
           "auth":"",
           "cardAcceptor":"",
           "mandateID":"",
           "instalment":""
}
